## V1 问题与 V2 改善证据

### 状态机与 Tool Contract

V1 中 6 例重复搜索或读取证据后耗尽请求、4 例过早 `set_plan` 后无法恢复。V2 用阶段化工具集合阻止已取得目标品类结果后的重复搜索，并将缺证据的方案暂存，证据补齐后由控制器做一次有界提交。N01、N03、H02、H05、H06、E02、B02、B03 等因此通过。模型平均请求从 5.12 降到 4.33，工具调用从 6.05 降到 5.25，说明改善并非来自提高调用上限。

### 动态修改事务

数量和删除操作基于已有 plan 做局部修改；替换通过 `replace_item` 在新报价证据、预算和约束校验全部通过后原子提交。D02 的数量和金额同步，D03/D05 的移除与保留关系正确，D06 的键盘替换不再产生中间空方案，D08 的未修改条目保持不变。动态修改增加 6 个通过案例且没有退步。

### 成功状态保留与错误恢复

C04 在 V1 中已经 `set_plan` 成功，却因最终自然语言请求失败而返回空状态。V2 将已验证任务状态与最后回复解耦，并保留确定性摘要 fallback；C04 本次通过。工具 schema 错误也返回允许字段、错误码和状态未变信息；B02 不再向 `update_constraints` 传入只读 `scope`。

## V2 剩余 Badcase

V2 有 7 个端到端失败案例。以下按主要根因互斥归类；原始 Trace 保留全部伴随因素。

| 主要层级 | 数量 | 案例 | 证据与判断 |
|---|---:|---|---|
| 约束状态结构化 | 2 | H03、H04 | H03 已形成键盘+台灯方案，但 `owned` 未写入“鼠标”；H04 只把“不含显示器”写入自由文本 constraint，`excluded` 为空。方案内容合理，但服务端结构化约束不完整。 |
| 终止条件 / 首轮基线缺失 | 2 | D04、B01 | D04 首轮已搜商品并读证据却未 `set_plan`，第二轮无法执行“删除并保持”；B01 读完两条证据后发起非必要追问，没有提交未确认方案。 |
| 工具副作用与恢复 | 1 | D01 | 降预算时 `update_constraints` 已自动移除台灯，随后又调用 `update_item(remove)`，产生可避免的失败工具事件。最终状态和动态断言正确，但严格 Tool correctness 失败。 |
| 外部搜索错误重试 | 1 | E05 | 固定搜索故障后以完全相同参数重复调用一次，触发同轮重复工具断言；系统没有编造商品或错误提交方案。 |
| 固定评测响应语义 | 1 | E03 | 固定摘要自称“评测占位项”，模型据此拒绝形成价格未知候选。为保持 V1/V2 公平，本次未修改夹具；这是已披露的可比性限制。 |

V2 相比 V1 有 14 例任务由失败转为通过，H04、E05 两例由通过转为失败。H04 是结构化 excluded 遗漏，E05 是故障后的同参数重试；两项都应作为下一轮回归重点，不能用 33/40 掩盖。

## 人工抽查与运行用量

人工抽查 12 例，覆盖 7 个 V2 失败、动态修改成功与失败、状态恢复和购买边界；12/12 与自动判分一致。评分完全基于最终状态和 Trace，没有使用 LLM Judge。

正式 V2 共发出 173 次模型请求、执行 210 次工具调用，40/40 均实际运行，没有跳过或资源不足。172 次请求取得可计价 usage，按 2026-09-08 记录的 DeepSeek 官方费率估算已知费用为 **¥0.900465**；1 次费用未知。该金额是 usage 估算，不是供应商账单。持久调用预算结束时为 487/555，剩余 68。V2 比 V1 少 32 次模型请求和 32 次工具调用。

## 复现

代码基线固定在 `eval-v2-candidate`。配置本机 `.env` 和独立调用预算后运行：

```powershell
python evaluate_agent.py --prompt shopflow-v2 --label eval-v2 --git-tag eval-v2-candidate --max-calls 240 --output reports/agent-eval-v2-final.json
```

评测输出记录代码 commit、Prompt 和 benchmark 哈希、逐案例输入/输出、任务状态、Trace、评分、模型 usage 与费用估算。供应商的非确定性响应可能使复跑数字变化；固定搜索响应和确定性判分保证数据与评分部分不漂移。

## 可用于简历的真实数字

> 为 ShopFlow 搭建覆盖 40 个端到端采购任务、88 项硬约束和 8 个动态修改场景的可复现 Agent 评测体系；基于逐案例 Trace 将失败定位到状态机、工具契约、动态事务和错误恢复层，在相同 benchmark、固定搜索响应、DeepSeek 模型与评分口径下复测，使端到端任务成功率由 21/40（52.5%）提升至 33/40（82.5%），动态修改成功率由 1/8（12.5%）提升至 7/8（87.5%），工具调用正确率由 24/40（60.0%）提升至 34/40（85.0%），边界违规率保持 0/40。

这组数字可以描述本次冻结配置下的实验结果。它不等同于线上用户成功率，也不衡量实时全网搜索质量，因为正式比较使用了固定搜索响应。
