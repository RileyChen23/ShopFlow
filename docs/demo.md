# 3—5 分钟演示与真实试用指南

## 演示前

运行 python server.py，打开本地页面。要展示故障，启动前设置 ENABLE_TEST_LAB=1。默认离线规则模式与测试商品标签必须保留。不能口头声称已连接真实模型或外部测试店铺。

## 0:00—1:40 组合采购

1. 新任务，选择演练资料。输入“预算 1000 元改善学习桌面，我已经有笔记本和鼠标。”
2. 回答澄清：“主要改善照明和打字，预算 500 元。”看到键盘 159 元 + 台灯 99 元，已知小计 258 元，不采购已有鼠标。
3. 输入“预算降到 300 元”，确认右侧预算同步。移除台灯，小计 159 元。替换键盘为蓝牙款后变为 229 元。
4. 展开来源：测试样品与固定报价明确标注，运费、库存未知。点击核对方案，逐项确认 SKU、规格和数量。
5. 创建入口，进入本地结算演练，再点击“完成演练（不付款）”。明确这不是 Shopify，也没有生成真实订单。

若已完成用户自己的 Shopify 集成验收，可以另选导入的 TEST- SKU 展示外部测试 checkoutUrl；目前这一段仍待配置，不用本地模拟替代宣称成功。

## 1:40—2:30 明确单品与真实资料

新任务输入“想买一个 300 元内的键盘，晚上在宿舍用。”直接形成单品方案，无冗长问卷或强制套装。

切到真实资料浏览官方依据；可新建 GBP 任务查看 K380s。中国市场实时报价缺失，不能用测试报价证明预算可行。小米资料页不是购买页。外部英国商品按钮为“前往购买”，不叫直接支付。

## 2:30—4:00 故障与迭代

进入 /lab 注入检索超时。显示错误并进入 /runs，查看失败阶段与原方案保留。确认后的结算故障同样不会显示假成功。

打开 /evaluation：说明系统测试结果与 32 例离线评测口径。用 D07 解释必要品被可选品挤占预算的 baseline 问题，再看 v2 修复和 H14 回归。真实模型结果标为未运行。

最后刷新工作台，方案仍在。偏好由用户明确保存，预算不会成为长期消费画像。

## 真实试用（尚未开展）

招募 5—8 位有近期真实学习/办公采购任务的目标用户。先说明记录内容、使用范围和删除方式，征得同意；不采集支付信息。试用者使用自己的会话，不共享任务 cookie。

给出任务而非教按钮：请描述一个近期真实想买/改善的问题，讨论并改一次方案，指出是否愿意继续购买以及犹豫点。观察候选是否缺失、澄清是否烦扰、证据是否有用、修改是否顺畅、费用说明是否足够。

记录任务背景、成功条件、关键停顿、错误分类、完成时间、帮助程度评分与原话；未购买的原因同样重要。测试资料演示与真实采购分开，不把模拟完成率算购买转化。

如果比较传统购物方式，用相近难度的不同任务，交替任务顺序控制学习效应。样本少只能形成方向线索。没有实际执行前，访谈人数、满意度、时间节约与转化提升都保持“待验证”。
